# Events SEO and dynamic discovery (version-16)

The existing ERP Developers Event DocType remains the source of truth.
The /events directory uses the existing published/regional allowlist, database
pagination (12 per page), country/topic/format/period filters and a bounded
title search. A small progressive-enhancement script submits filters on change
and search after 450ms; the Apply Filters button remains functional without JS.

## Detail pages and indexing

Published, region-relevant events have individual routes:
`/events/<normalized-English-title>-<immutable-DocType-name>`.

The controller obtains the immutable ID from a bounded route argument and
fetches public allowlisted fields only. Unpublished, non-regional or unsafe
legacy-link records never render. Old title-based URLs continue looking up the
immutable ID; canonical points to the current title route.

Detail pages provide:
- server-rendered event title, description, image and official source link;
- canonical URL and description;
- JSON-LD Event data, including actual event start/end, organizer, attendance
  and location modes, explicit cancellation/postponement;
- no fabricated prices, ratings, tickets, performers or physical locations.

The directory page is indexable. Faceted/search/paginated query URLs are
noindex/follow. Detail pages can be crawled through directory hyperlinks.
**Per-event sitemap entries, distinct language alternates, and production
Google Rich Results validation are not yet implemented or verified.**

No event is imported or auto-published. Existing public image permissions
and source-verification rules remain unchanged.

## Release verification required

1. Run existing source test suite and `python -m unittest tests.test_event_seo`.
2. On a Frappe 16 staging site, migrate/build, clear cache, and verify
   /events, filtered searches, /events/<slug>-<id>, 404 for unpublished
   records, canonical metadata, Arabic rendering and Event JSON-LD.
3. Validate example URLs with Google Rich Results Test and inspect sitemap
   coverage in Search Console.
4. Promote to production only after a backup and operator-approved validation.

Source commits to version-16 are **not** a production deployment.
